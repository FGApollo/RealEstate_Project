## Root cause of the screenshot

`/` mounted the customer `Home` directly after restoring the server session. Only private routes checked the destination role. The shared header also always rendered customer links and `/profile`. An Admin opening the site root therefore saw a customer page with the correct Admin identity. This was a routing/menu bug; it does not by itself demonstrate backend privilege escalation.

`SessionRoute` now waits for the server session and sends ADMIN to `/admin`, AGENT to `/sale/overview`, and USER/guest to `/`. Authenticated login/register pages redirect consistently. Header navigation, private-route guards and stored pending actions use the same role policy. Staff logins cannot resume stale customer favorite/profile actions. Role changes returned by refresh update the mounted guards immediately. Forged local storage is ignored and the old user/history caches are removed.

## Confirmed findings and changes

| Area | Finding | Implemented remediation |
|---|---|---|
| Supabase data access — critical | Anonymous HEAD/count requests succeeded for sensitive application tables including users, identity verifications, messages, OTPs and favorites. This bypasses Express authorization. No records/documents were fetched. | Migration 011 revokes table **and column** grants, owned-sequence access and known app-RPC execution from PUBLIC/anon/authenticated; enables RLS; preserves service_role. It restricts direct storage writes and private-document reads. **Verified on production after the user applied SQL.** |
| KYC decisions — critical | Real Face++ mismatch/provider errors could fall back to an approximate demo that approved identities. | Real provider failures/mismatches fail closed. Demo face/OCR approvals require explicit local/test configuration and cannot run in production. Face++ endpoint/redirects and response bounds are constrained. |
| Authentication | Disabled/unknown-status accounts and unknown roles were not consistently rejected; malformed session expiry could pass checks. | Password/Google login, session creation, access and refresh require an active account and known role. Sessions and JWT claims fail closed. Creation rereads DB identity; refresh rotates atomically. |
| Session lifecycle | Late refreshes/401s could overwrite a newer login or replay an earlier account's mutation. Cross-tab refresh failures could delete a newly rotated shared cookie. Password changes left old sessions valid. | Generation checks protect refresh and private requests; refreshes share a promise and use browser locks when available. Origin/path-scoped bearer headers prevent accidental external transmission. A cross-account refresh expires the tab without replaying a mutation. Stale refresh401 never clears another tab's newer cookie. Logout revokes cookie and signed bearer session. Password changes revoke every session; verified credential proofs prevent delayed old-password login from creating a new session. |
| CSRF / cookies | Cookie-bearing requests without a positive trusted Origin were accepted. | Exact origin allowlist, trusted-Origin checks on cookie endpoints, HttpOnly/secure cookie policy and no-store session/API responses. Business APIs continue to require bearer authentication. |
| Phone verification | Editing a phone kept its old verified flag. OTP attempt increments/consumption were separate read/write operations, plaintext codes were stored and demo delivery was possible in production. | Phone changes clear verification; conditional profile updates prevent overwriting a phone verified concurrently. Migration 013 locks consumption and phone-state updates, caps attempts at five and makes each code single-use. New rows store an account/phone-bound HMAC, not the code; legacy codes are invalidated. Production rejects mock/sandbox delivery and cannot verify test OTPs. |
| Private documents | KYC used public URL fields and fetched arbitrary stored URLs. Evidence used a public bucket/public local fallback; upload previews would break after moving private. | Private object references, exact same-project legacy URL conversion, owner checks and authorized 5-minute signed previews. No arbitrary server URL fetch. Evidence UI previews signed URLs but submits owned references. Arbitrary external evidence URLs are removed. Local evidence is denied even with URL-encoded filenames. |
| API ownership/privacy | Favorites bypassed the public listing projection and could include hidden listings/contact details. Voter identities and reporter identities were exposed unnecessarily. | Favorites/similar/public listings use safe projections and visibility rules; reviews return vote counts/current-user status; accused agents never receive reporter identity. Chat validates participants, property attachment relationship and pagination; edits continue to enforce ownership. |
| Inputs / uploads | MIME labels alone did not prove image contents; listing/review IDs, values, image counts and body sizes were insufficiently bounded. | Decode/reencode JPG/PNG/WEBP, 5MB/20MP caps, EXIF/GPS removal, bounded multipart/JSON inputs, positive IDs, field/rating/page limits and owner-scoped image deletion. SVG/script inputs are rejected. |
| Trust score | Concurrent one-time claims/refunds could duplicate bonuses or separate score writes from logs. | Migration 012 serializes account score mutations and logs in one SQL transaction, with idempotent one-time/KYC/report-refund actions. Missing RPC fails closed. Report resolution follows a successful score operation and can recover a later failed status write. |
| Response hardening | Raw DB/provider errors leaked through several controllers; common browser protection headers were missing. | Safe controller fallbacks, parser/error handling, API no-store, nosniff, frame restrictions, HSTS in production, Vercel CSP and private local-file denial in Vite. |
| Dependencies | npm reported known advisories in direct/transitive packages. | Compatible patched versions and lockfiles: Axios 1.20.0, React Router 7.18.4, Multer 2.4.0, Sharp 0.35.5, proxy-addr 2.0.8, qs 6.16.1 and related fixes. Both npm audits report zero known vulnerabilities at verification time. |

One legacy evidence image was removed from `server/public/uploads` and preserved in ignored `.local/private-legacy-evidence` for an authorized private import. It is denied by the dev server too. Git history was not rewritten: if historical evidence contains sensitive information, deleting the current file alone does not remove earlier repository copies.

## Production steps and limits

The database step (011 → 012 → 013) is complete and verified. Follow [the deployment guide](server/db-migration/011-DEPLOYMENT.md) to deploy both backend/frontend and configure production providers. The read-only `server/scripts/verify-security-access.cjs` check can repeat public-key validation and the 22 anonymous HEAD denials. Then verify legitimate login/refresh, Admin, listings, KYC/evidence and real SMS paths using staging accounts. Unavailable real providers must remain unavailable, never demo-approved.

This review covered the application source, route/service authorization, session behavior, local dependency advisories and read-only Supabase exposure checks. It did not perform an authenticated production penetration test, inspect historical access logs, rotate live secrets, rewrite repository history, or verify third-party provider credentials. It cannot establish whether existing exposure was previously exploited. Keep future app migrations private explicitly; migration 011 deliberately leaves unrelated extension objects untouched.
